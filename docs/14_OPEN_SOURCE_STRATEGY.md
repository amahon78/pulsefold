# Open Source Strategy

## 1. Goal

PulseFold should be genuinely useful as an open source project without a hosted service.

No artificial degradation of the core project is planned.

## 2. Repository qualities

- clear README
- reproducible examples
- public roadmap
- architecture docs
- benchmark methodology
- security policy
- contribution guide
- code of conduct before community scaling
- issue templates after first public release

## 3. Licence

Not yet locked.

Preferred candidate for review: Apache License 2.0 due to common use in infrastructure projects and explicit patent provisions.

Final selection should occur before the public repository accepts external contributions.

## 4. Credibility

The project should publish:
- benchmark results
- limitations
- failure cases
- evaluation methodology
- architecture decisions

Avoid inflated claims such as "replaces Datadog" until demonstrated.

## 5. Employer separation

Public development artefacts must not include:
- employer source code
- employer credentials
- employer customer data
- private production logs
- private invoices
- private architecture diagrams

Reference environments should be synthetic or public.
